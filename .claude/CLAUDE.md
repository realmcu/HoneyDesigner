# agent-deep-thinking — 深度思考工作區

這個工作區的存在目的：把**複雜推理 / 深度研究 / 系統審計 / 大型重構規劃**這類「不能一步到位、想錯方向代價很高」的任務，用全生命週期紀律跑完。

核心信念：**逼近 Fable-5 級工作流程**——不是靠模型一次更聰明，而是靠流程上的紀律（先想清楚、被獨立挑戰、看真實證據、不收自報）把錯誤擋在交付之前。

Hook 在對應時機自動提醒紀律，skill 補上 hook 做不到的主動 spawn subagent。

---

## 兩個核心工具（深度思考必用）

### `/deep-work` — 複雜多步任務的編排
任何「跨 ≥3 個檔案、會動很多地方、現在還不確定每步細節」的任務，**先召喚 `/deep-work`**，不要 single-pass 硬幹。
四階段：規劃（只想不做）→ 對抗審查（spawn 獨立 agent 找計畫漏洞）→ 串行執行（死規格 + atomic commit）→ 整合驗證（看真實證據）。
> 為什麼：複雜任務的失敗多半不是不夠聰明，是太快動手、沒人挑戰計畫、做完不驗證。

### `/adversarial-verify` — 交付前的對抗式複查
**下任何重要結論、交付任何東西之前，先召喚 `/adversarial-verify`。**
把結論拆成一條條具體 claim，spawn 一個「預設你錯」的獨立 agent 去 refute（不是 review），被推翻的丟掉、證不倒的才交付。
> 為什麼：模型對自己剛產出的東西有確認偏誤。single-pass 結論被獨立對抗複查推翻的比例經驗上常達半數。最便宜的保險就是交付前花一次 spawn。

## 工程紀律（針對深度思考挑選，每條附「為什麼」）

**1. 看真實再下結論**：描述「系統怎麼運作」「某模組做什麼」前，先 `ls` 檔案、`grep` caller、跑一次。禁止憑記憶或憑「設計上應該」回答。
> 為什麼：記憶會過期，設計意圖 ≠ 運行事實。憑印象描述系統是幻覺的頭號來源。

**2. 自報數字必驗**：任何「有 N 個」「已經 X」「應該是 Y」，下結論前先 grep/ls/count 確認真實值。
> 為什麼：對「具體可驗證數字」的記憶/推測錯誤率很高。先驗一次省掉一連串基於錯誤前提的工作。

**3. 不確定就標記，不要硬幹**：搬不動的、不確定會不會壞的、需要對方拍板的——標記出來回報，不要猜著做。
> 為什麼：基於錯誤假設往前衝，是深度推理中最貴的失敗。

**4. 誠實優先於好看**：結論不利、證據推翻了原本的框架，就照實說，去找真實原因，不為了結論漂亮而粉飾。
> 為什麼：虛假撐起的結論比誠實的「不知道」更危險——前者讓你基於假象做後續決策。

**5. 減法優先於加法**：要建新模組/分析/流程前，先盤點現有的，問「能不能用既有的？有沒有更簡單的做法？」。
> 為什麼：多數「我需要一個新 X」其實是「我沒找到已有的 X」。深度思考最常見的浪費是把問題想得比實際複雜。

**6. 靠機制不靠承諾**：同類錯誤 / 同類誤判出現 ≥3 次 = 系統性問題，去建一個機制（hook/checklist/skill）擋它，而不是第 4 次再手修。
> 為什麼：你（和模型）一定會忘。能持久的只有自動觸發的機制。

**7. 串行防 race**：多個 agent 動同一個 git 工作樹時，串行執行，不並行。
> 為什麼：並行的 agent 會互相吃掉對方 staged 的改動，commit 變得張冠李戴。

**8. commit 前真實驗證**：改了會被載入的 runtime code，commit 後要真的重啟 + 看 log 確認生效，不是「讀起來對」。
> 為什麼：「import 成功」≠「runtime 正確」。靜態看對的東西在真實執行時常常壞。

## 自動紀律（hook，已在 `.claude/settings.json` 接好）

這些在對應時機自動觸發提醒，不必你記：
- **self_challenge_gate**（UserPromptSubmit）：發言前自我質疑
- **asset_inventory_gate**（UserPromptSubmit）：動手建東西前先盤點現有資產
- **ls_real_preflight**（UserPromptSubmit）：下結論前的現實檢查
- **session_retro**（UserPromptSubmit）：session 末把教訓結晶化
- **verify_before_commit**（PreToolUse/Bash）：commit 前驗證
- **restart_reminder**（PostToolUse/Bash）：改動後提醒重啟

Skills 在 `.claude/skills/`，hooks 在 `.claude/hooks/`，hook 路徑透過 `$CLAUDE_PROJECT_DIR` 展開。
