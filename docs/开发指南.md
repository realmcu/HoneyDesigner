# HoneyGUI Design 开发指南

本文档是项目维护者的长期技术入口。仓库协作、国际化和安全约束以根目录 `AGENTS.md` 为准，
发布流程见根目录 [`RELEASING.md`](../RELEASING.md)。

## 项目定位

HoneyGUI Design 是一个离线优先的 VS Code 扩展，提供以下完整工作流：

```text
创建项目 -> 可视化编辑 HML -> 转换资源 -> 生成 C 代码 -> PC 编译仿真 -> UART 下载
```

代码生成支持 HoneyGUI 和 LVGL 两个目标引擎，由项目 `project.json` 的 `targetEngine` 决定。

## 技术栈

- TypeScript 严格模式、VS Code Extension API
- React 19、Zustand、Webpack 5
- `fast-xml-parser` 处理 HML
- Three.js、Lottie 等用于特定组件预览
- SCons 用于 HoneyGUI 仿真，CMake 用于 LVGL PC 仿真

## 扩展启动

`src/extension.ts` 创建 `ExtensionManager`。管理器注册命令、侧边栏、状态栏、HML 自定义编辑器、仿真服务和 UART 服务，并检查当前工作区项目。

扩展还启动仅用于本机设计工作流的 HTTP API。项目启用 AI 资产时，扩展把 `vibe-designer/skills/honeygui-designer/` 分发到项目，并维护项目根 `AGENTS.md` 的托管区块。

## HML 编辑链路

### 打开文件

`.hml` 由 `HmlEditorProvider` 作为 `CustomTextEditorProvider` 打开。每个面板拥有独立的 `HmlController`，由 `DesignerPanel` 组装以下模块：

- `FileManager`：加载、保存、重载、文件快照和跨文件扫描
- `MessageHandler`：Webview 到扩展端的消息入口
- `SaveManager`：保存事务与并发编辑保护
- `AssetManager`：资源扫描、选择和转换配置
- `ComponentManager`：组件相关宿主操作

### 初始加载握手

初始数据必须等待 Webview 就绪：

```text
resolveCustomTextEditor
  -> FileManager.loadFromDocument（只解析）
  -> Webview 发送 ready
  -> MessageHandler 发送项目配置
  -> FileManager.reloadCurrentDocument
  -> Webview 收到 loadHml
```

`loadHml` 除当前组件外，还包含项目配置、项目国际化目录、所有 HML 文件和视图、其他文件组件 ID、GUI 版本以及仿真状态。加载阶段会把 `hg_view` 的显示尺寸校正到项目分辨率。

### 外部修改和保存

编辑器同时监听 VS Code 文档变化和磁盘文件变化，以支持文本编辑器、AI 工具、格式化器和 Git 操作。监听器通过防抖、保存事务 ID 和 `PendingWriteRegistry` 避免循环重载。

Webview 的 Zustand Store 保存内存编辑态，并向宿主报告脏状态。保存时 Webview 发送组件数据，扩展端更新 HML 文档、序列化并应用 `WorkspaceEdit`。撤销和重做同样发往扩展端，由 `FileManager` 的内容快照处理。

## Webview 结构

```text
App
├── Toolbar
├── 左侧面板
│   ├── ComponentLibrary
│   ├── AssetsPanel
│   └── ComponentTree
├── DesignerCanvas
└── PropertiesPanel / ConversionConfigPanel
```

`DesignerCanvas` 使用 React DOM 渲染组件，负责缩放、平移、拖拽、调整尺寸、框选和对齐。它不是 Fabric.js 画布。特定 3D 组件和资源预览才使用 Three.js。

`App.tsx` 目前承担宿主消息分发，`store.ts` 管理组件、选择、剪贴板、画布、脏状态、项目配置、项目国际化和导航关系状态。

## 代码生成

`CodeGenerationService` 找到项目后调用 `CodeGenerator`。后者扫描 HML 文件、解析组件并读取项目配置，再由 `CodeGeneratorFactory` 创建目标引擎生成器：

```text
project.json.targetEngine
  ├── honeygui -> HoneyGuiCCodeGenerator
  └── lvgl     -> LvglCCodeGenerator
```

生成文件遵循不同生命周期：

- `*_ui.c/h`：每次生成覆盖
- `*_callbacks.c`：保护区外可更新，保护区内用户代码保留
- 用户源文件：只创建一次，不允许生成器覆盖

共享资源、项目国际化、入口视图和 ROMFS 配置通过 `CodeGenOptions` 传入生成器。

## 编译仿真

`SimulationService` 接收命令并创建 `SimulationRunner`。Runner 按流程执行代码生成、资源转换、构建和运行。

- HoneyGUI：使用 `lib/sim/` 中的预编译库和 SCons 构建流程。
- LVGL：使用 `lvgl-pc/` 中的 CMake 工程配置、编译并启动模拟器。

修改仿真流程时必须同时检查两个引擎分支，不能假设它们共享相同的底层构建命令。

## 浏览器版

`src/web/` 构建出一个可静态部署的离线站点（`dist/web/`），用于在浏览器中编辑 HML、管理资源和生成 C 代码。它不参与 VSIX 打包，也不需要后端服务。

### 复用方式

浏览器版不重写宿主逻辑，而是在页面内运行与扩展相同的 `DesignerPanel`、`FileManager`、`MessageHandler`、`AssetManager` 和代码生成器。`webpack.web.config.js` 把它们依赖的模块替换为 `src/web/shims/` 下的浏览器实现：

| 模块 | 浏览器实现 |
|---|---|
| `vscode` | `shims/vscode.ts`：消息框、输入框、快速选择、进度交给 `host/hostUi.ts` 渲染；`WorkspaceEdit`、`FileSystemWatcher`、`TextDocument` 落到内存文件系统 |
| `fs` | `shims/fs.ts`：同步内存文件系统，写操作通过 `vfs.onChange` 广播 |
| `crypto` | 同步 SHA-1 / SHA-256 |
| `child_process` | 进程启动立即以 `ENOENT` 失败，调用方走已有的降级分支 |
| `zlib` / `util` / `stream` / `assert` | 覆盖 `pngjs` 同步编解码所需的最小实现（`zlib` 基于 `fflate`） |

`SimulationService` 由 `src/web/stubs/` 替换。清理、串口下载和资源转换命令在 `host/browserHost.ts` 中注册为提示对话框，并回发 `operationComplete` 复位工具栏忙碌态；仿真命令由 `src/web/sim/` 实现，见下文「浏览器仿真」。

### 运行链路

```text
ProjectLauncher（新建 / 导入 ZIP / 打开本地文件夹 / 从 GitHub 导入）
  -> projectStore.loadProjectIntoVfs：工程文件读入内存文件系统
  -> browserHost.openDesigner：创建 BrowserWebviewPanel + DesignerPanel，解析主 HML
  -> React App 挂载并发送 ready -> MessageHandler 推送 loadHml（与扩展相同的握手）
  -> ProjectSync：监听内存文件系统变化，批量回写 IndexedDB 或本地目录
```

- `BrowserWebviewPanel` 用 `window.postMessage` 模拟 webview 消息通道，两个方向都做结构化克隆，保持与 VS Code 相同的值语义。
- 资源 URL 由 Service Worker（`src/web/sw.ts`）提供：`/__vfs/<路径>` 向页面索取内存文件内容，保留目录结构以便 3D 模型按相对路径加载贴图。Service Worker 不可用时退回 `blob:` URL。
- Service Worker 同时按构建生成的 `precache-manifest.json` 预缓存全部静态资源，首次访问后可离线使用。
- 「打开本地文件夹」使用 File System Access API，仅 Chromium 内核浏览器支持；其他浏览器使用浏览器存储和 ZIP 导入导出。
- 所有导入入口都经 `ProjectLauncher.persistProject` 落库：先写文件、再写工程记录，任一步失败就删掉**本次新工程 ID** 下的写入，不会留下半成品记录，也不会触碰已有工程。

### 从 GitHub 导入

`src/web/host/githubImport.ts` 负责取数与校验，`src/web/ui/GitHubImportDialog.tsx` 负责交互。

弹框的「模板」下拉来自 `exampleProjects.ts` 的 `GITHUB_TEMPLATES`，由 `TemplateConfig.ts` 的 `AVAILABLE_TEMPLATES` 推出：取仓库名换成 `github.com/realmcu/<仓库名>`（与 CI 克隆模板的地址一致）。新增模板只改 `TemplateConfig.ts`。选「自定义地址」可粘贴任意 GitHub 地址。下载前后都显示来源链接，指向本次实际下载的 commit。

**同一来源只保留一份副本**。工程记录里存 `sourceKey`（`github.com/<owner>/<repo>[/<工程根>]`，owner/repo 转小写，不含分支和 SHA）和 `sourceRevision`（下载时的 commit SHA）。选定工程后先按 `sourceKey` 查浏览器副本：

- 没有：照常新建。
- 有：提示是否已是仓库当前版本（比较 SHA），让用户选「打开已有副本」或「重新下载并覆盖」。
- 覆盖沿用原工程 ID，由 `projectStore.replaceBrowserProject` 在**同一个 IndexedDB 事务**里删旧文件、写新文件、更新记录，失败整体回滚，旧副本不受影响。覆盖会丢掉浏览器中对该副本的修改，提示文案要写明。

浏览器无法下载仓库归档包：`codeload.github.com` 的 CORS 白名单写死为 GitHub 自家域，`github.com/*.zip` 也只是 302 到 codeload。因此走「列目录 + 逐文件取正文」，分两条通道，由 `resolveSource` 选择：

```text
快速通道（默认，不消耗 GitHub REST 配额）
GET data.jsdelivr.com/v1/packages/gh/{o}/{r}@{ref}?structure=flat   确认 ref 并取文件清单（路径、大小、sha256）
GET cdn.jsdelivr.net/gh/{o}/{r}@{ref}/{path}                        逐文件取正文

API 通道（快速通道失败时降级）
GET api.github.com/repos/{o}/{r}                      确认仓库
GET api.github.com/repos/{o}/{r}/commits?sha={ref}    把 ref 解析成 commit SHA
GET api.github.com/repos/{o}/{r}/git/trees/{sha}?recursive=1
GET raw.githubusercontent.com/{o}/{r}/{sha}/{path}    逐文件取正文
```

REST 未认证限额是按 IP 的 60 次/小时，公司出口共享一个 IP 时很快用完，因此默认走快速通道；示例工程不打包进站点，始终从仓库实时拉取。快速通道的取舍：

- jsDelivr 对超过 50 MB 的仓库包返回 403，此时降级到 API 通道。降级前（以及 API 首次调用返回主限额耗尽时）若 API 配额已用尽，报 `channel-unavailable`（「仓库超出快速通道上限且 API 配额用尽」），不能只报限流，否则用户看不出与体积有关。
- jsDelivr 清单不带文件 mode，**这条通道上无法识别子模块和符号链接**，下文的子模块/符号链接拒绝规则只在 API 通道生效。需要严格校验时用 `forceApi`。LFS 指针仍靠下载后嗅探正文识别，两条通道一致。
- 不能用 `github.com` 的 Atom 订阅源或其他页面解析 SHA：它们不回 `Access-Control-Allow-Origin`，浏览器里必然被挡，结果每次都降级到 API。
- jsDelivr 没有免配额且放行 CORS 的接口能把分支解析成 commit（按分支请求时 CDN 的 `X-JSD-Version` 只回显分支名）。因此分支导入不固定 commit（`pinned: false`，`sha` 为空），清单和正文都按分支名取；地址里没写分支时用 `HEAD`。正文下载后按清单里的 sha256 校验，不一致整体失败，避免取到清单之后分支被推新导致内容混杂。只有用户贴的是 commit 链接时才固定到 SHA。
- `{ref}` 整段 `encodeURIComponent`：含 `/` 的分支名不编码时，清单接口返回 400，CDN 则把第一段当分支、其余当路径。
- 「已是仓库当前版本」只在固定到 commit 时判断；按分支导入的副本无法比较，总是让用户选择。
- 取消不算降级信号，原样向上抛。jsDelivr 的其他失败（网络、5xx、解析失败）一律降级。

必须遵守的约束：

- **限额按次扣减**。API 通道每次响应后重读 `X-RateLimit-Remaining` / `X-RateLimit-Reset`，用完即停，不假设固定调用次数。`raw.githubusercontent.com` 的响应没有这些头，但不能据此认定它不占额度。
- **ref 用「最长候选优先」解析**。分支名允许含 `/`，不能取第一段当分支，也不能用 tree 顶层目录反查。依次把 `[全部段, 前 n-1 段, …]` 当作 ref 确认（快速通道请求 atom，API 通道调 commits 接口）；**只有 404 才继续回退**，遇到 403/429 必须立即中止，否则限流会被误判成「ref 不存在」。
- **所有正文固定用解析出的 commit SHA 下载**，不用分支名，避免下载途中分支被推新导致文件集不一致。
- **完整性优先于可用性**。工程范围内出现子模块（`type: commit` / `mode: 160000`）或符号链接（`mode: 120000`）即拒绝并列出路径；仓库其他目录有这些不影响当前工程。`truncated: true` 的仓库直接拒绝，不返回残缺清单。下载到 Git LFS 指针（正文以 `version https://git-lfs.github.com/spec/v1` 开头）即整体失败 —— tree 里的 `size` 对 LFS 文件是指针大小，不能当作真实体积。`.gitattributes` 里的 `filter=lfs` 只作提示，它带目录作用域和覆盖优先级，不能据此直接判定。
- **200 MB 是绝对上限**，不随预估值放宽；tree 估算超限时在下载前拒绝，下载过程按块累计真实字节，达到上限立即 `cancel()` 读取流。50 MB 以上要求用户确认。
- **取消要延续到底**。取消后停止派发新请求并中止在途请求，落库阶段同样检查取消标记。落库成功才算提交。
- **错误分类按响应头判断**：`Remaining = 0` 是主限额耗尽（用 reset 时间提示）；有 `Retry-After` 或明确二级限流信息是次级限流；其他 403 是访问被拒绝，不编造恢复时间。404 无法区分「仓库不存在」和「私有仓库」，措辞要同时覆盖两种可能。
- **Gitee 不支持**。`gitee.com` 的 raw 与 archive 都不回 `Access-Control-Allow-Origin`，`api/v5` 的 trees/contents 可用但文件正文按次扣 60 次/小时限额，一两百个文件的模板走不通。识别到 Gitee 地址时给出改用 GitHub 镜像或导出 ZIP 的提示（`realmcu/*` 在 GitHub 上有对应镜像）。

### 浏览器仿真

浏览器版仿真只支持 HoneyGUI 工程，运行在 HoneyGUI SDK 的 `simulator/web` 引擎（WebAssembly）上。引擎由 `scripts/build-web-engine.js` 用 SDK 的 `.config_engine` 构建到 `lib/web-sim/`（`update-sim-assets.yml` 与原生仿真库一起同步，需要 emsdk），`scripts/prepare-web-sim.js` 在 `build:web` 之后把它部署到 `dist/web/sim/`。

仿真窗口提供两种方式，按工程记在 `localStorage`（`honeygui.web.simulationMode:<工程 ID>`）：

- 快速预览：资源转换后由引擎的 HML 运行时解析 `ui/*.xml`，不编译工程 C 代码，保存后自动刷新。新建和导入的工程默认用它。
- 完整仿真：与桌面版相同的代码生成，再由构建 Worker 里的 WASM clang / wasm-ld 编译链接成 `project.wasm`，经 binaryen 做 Asyncify 变换后交给引擎加载，工程 C 代码（`callFunction`、回调、自定义定时器）都会执行。从内置示例打开的工程（`sourceKey` 为 `example:<id>`）默认用它；入口视图在 HML 里没有组件、由切入函数用 C 代码绘制的工程（`entryViewDrawnByCode`）也默认用它，这类工程在快速预览下画面空白，窗口会给出醒目提示和切换按钮。

编译器约 105 MB（传输时压缩到约 30 MB），只在确实有单元要编译时下载。为了让示例不必下载编译器，`deploy-web.yml` 在 `prepare-web-sim.js` 之后运行 `scripts/prebuild-web-examples.js`，按浏览器的同一套规则（`src/web/sim/buildCore.ts`）编译 `src/web/examples/*.zip`，输出到 `dist/web/sim/prebuilt/`：

- `o/<单元键>.o`：每个编译单元的目标文件；`p/<工程键>.wasm`：整个工程；`index.json`：键列表与工具链标识。
- 单元键是工具链标识 + 编译参数 + 源文件 + 它 `#include` 的工程头文件的 SHA-256；工程键由全部单元键和链接参数得到。工具链标识（`toolchain.json` 的 `id`）随 clang、binaryen 版本和头文件包变化，变化后旧索引整体作废。
- 页面先算键：工程键命中直接下载 `project.wasm`；否则交给 Worker，Worker 依次取内存缓存、预编译目标文件，只有剩下的单元才加载编译器编译。用户改了界面后通常只有生成的界面文件需要重编。
- 预编译要求代码生成是确定的：生成代码不能带时间戳或绝对路径。脚本发现生成的源码里含有临时目录路径时会失败，因为这样的键在浏览器里永远对不上。浏览器不编 `app_romfs.c`（`compileRomfs` 默认关闭），预编译也不编。

浏览器里没有 FFmpeg，视频（含 `gifAsVideo` 的 GIF）由 CI 预转换：`deploy-web.yml` 装好 FFmpeg 后运行 `scripts/prebuild-web-videos.js`，克隆 `GITHUB_TEMPLATES` 里的官方模板、解开内置示例，用桌面版同一套规则（`BuildCore.planVideos` / `convertVideo`）转换，输出到 `dist/web/sim/videos/`：

- `v/<产物键><扩展名>`：转换结果；`index.json`：原始键 → `{key, ext}`。见 `src/web/sim/prebuiltVideos.ts`。
  - 两级键。**原始键**（`videoKey`）= 转换参数（`VideoSpec`）+ 源文件内容的 SHA-256，浏览器算得出来。**产物键**（`videoOutputKey`）= 原始键 + FFprobe 换算出的缩放像素尺寸，产物文件名用它。百分比缩放的像素尺寸必须读视频尺寸才知道，浏览器读不了，所以换算只发生在 CI 与桌面版；把换算结果并入产物键，就不存在「键相同而内容不对应」。
  - 键规则（`videoKeyVersion()`）由 `BuildCore.VIDEO_SPEC_FIELDS` 和 `CONVERSION_VERSION` 组成，写进 `index.json` 的 `version`，对不上则整个索引作废。往 `VideoSpec` 加字段时必须在 `VIDEO_SPEC_FIELDS` 里登记，漏了会编译报错，所以加字段不需要另外处理版本；只有「参数没变但产物变了」（FFmpeg 命令、编码参数、对齐/打包改动）才需要递增 `CONVERSION_VERSION`。
  - 键只取 `VIDEO_SPEC_FIELDS` 里的字段：往 `VideoSpec` 加不影响转换的字段（例如给界面用的原始配置）不会作废已有产物。
  - CI 用 `--cache` 目录按键保留已转好的产物，本次没用到的会被删掉；脚本先算原始键判重，再对该视频做 FFprobe，重复引用不会重复读。
- 页面通过 `convertAssets` 的 `videoSource` 按键下载；对不上（用户换了视频或改了转换参数）的视频跳过并在日志中报错，需要在 VS Code 插件里仿真。下载由 Service Worker 写入运行时缓存，之后离线可用。
- CINEPAK 一段视频要转一分钟左右，CI 用 `actions/cache` 保留 `--cache` 目录，只转新增或改动的视频。模板仓库更新不会触发部署，需要时手动运行 workflow。
- 以后如果要在浏览器里兜底转换，不能用 `@ffmpeg/core`（GPL，内含 libx264），应使用不含 GPL 组件的 LGPL 构建或 WebCodecs。

快速预览相关模块：

- `src/simulation/HmlPreviewSupport.ts`：HML 运行时（SDK `realgui/3rd/ezXML/loader`）与代码生成之间的差距表。运行时补齐组件或属性后同步删减；新增 HoneyGUI 组件时，如果运行时不支持，要加进来，否则用户看不到「快速预览中看不到的内容」提示。
- `src/simulation/HmlPreviewPrep.ts`：把带 `i18nKey` 的标签换成当前语言文本（运行时不读 `i18n/strings.json`），收集差距，计算字体需要的字符。
- `src/web/sim/simulationController.ts`：保存 HML 后只重写界面文件，引擎在下一帧重建当前视图（`web_sim_reload_hml`）。新图片、字体需要的新字符、`assets/` 或 `i18n/` 的变化会重新转换资源并重启引擎，停在原视图。运行时重载时保留被替换的文档，热更新累计 3 MB 后也会重启引擎，避免 10 MB 的引擎堆耗尽。
- 资源转换结果在会话内按「输入文件大小 + 修改时间 + 转换参数」缓存（`ConversionCache`），图片逐张转换并让出页面线程。

### 修改注意

- 宿主代码新增 Node 内置模块或 `vscode` API 时，需要同步补充对应替身，否则浏览器版会在运行时报错。
- 浏览器中的 HoneyGUI 应用线程只能通过 `gui_os_api` 创建和等待：引擎把线程实现为 Asyncify 协作纤程，直接调用 pthread 或忙等会让仿真卡死。
- 新增依赖本机工具链的命令时，把命令 ID 加入 `browserHost.ts` 的 `DESKTOP_ONLY_COMMANDS`。
- 模块级缓存如果以工程内相对路径为键，需要在 `Workbench` 关闭工程时清理。
- 浏览器版界面文本使用 webview 的 `t()`；替身中出现的宿主文本使用 `vscode.l10n.t()`，由 `shims/vscode.ts` 读取 `l10n/bundle.l10n.zh-cn.json`。

## 构建与测试

安装与标准构建：

```cmd
npm install
npm run compile
npm run build:webview
```

修改代码后必须执行：

```cmd
npm run compile && npm run build:webview
```

可用检查：

```cmd
npm run lint
npm run test
npm run test:e2e
npm run test:perf
npm run test:templates
```

`npm run test` 包含工具单元测试和 `src/test/jest` 下的源代码测试。扩展 E2E、性能和模板测试是独立脚本，不包含在默认测试命令中。

浏览器版：

```cmd
npm run typecheck:web
npm run build:web
node scripts/prepare-web-sim.js
node scripts/prebuild-web-examples.js
node scripts/prebuild-web-videos.js [--cache <目录>]
npm run serve:web
```

`build:web` 输出到 `dist/web/`，可部署到任意静态服务器。Service Worker 和目录访问要求 HTTPS 或 `localhost`。`prepare-web-sim.js` 把 `lib/web-sim/` 的仿真引擎与编译器放进 `dist/web/sim/`（加 `--preview-only` 只放引擎，完整仿真不可用）。`prebuild-web-examples.js` 预编译示例工程，需要 `npm install` 装好的 `@yowasp/clang` 与 `binaryen`。`prebuild-web-videos.js` 预转换视频，需要 PATH 中有 `ffmpeg`、`ffprobe` 和 `git`；两个预构建脚本都要在 `prepare-web-sim.js` 之后运行（它会清空 `dist/web/sim/`）。更新引擎需要已激活的 emsdk：

```cmd
node scripts/build-web-engine.js <HoneyGUI SDK 目录>
```

## 生成代码的公开 API

生成的 `*_callbacks.h` 是 `user/` 代码可直接包含的公开契约。HoneyGUI 预设动画目前只承诺稳定的 `<组件ID>_preset_animation_reset()` 控制接口；真实时间时钟变量必须保留在 `*_callbacks.c` 内并声明为 `static`。

`<组件ID>_timer_cnt` 不再由生成器生成。用户代码重播预设动画必须调用 `<组件ID>_preset_animation_reset()`；删除或更改任何曾经出现在生成头文件中的符号前，必须搜索全部官方模板、示例工程和可访问的客户工程，并提供替代接口。不能因为符号最初是实现状态，就假定外部代码没有依赖。
