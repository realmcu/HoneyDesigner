# HoneyGUI Design 开发指南

本文档是项目维护者的长期技术入口。仓库协作、发布、国际化和安全约束以根目录 `AGENTS.md` 为准。

## 项目定位

HoneyGUI Design 是一个离线优先的 VS Code 扩展，提供以下完整工作流：

```text
创建项目 -> 可视化编辑 HML -> 转换资源 -> 生成 C 代码 -> PC 编译仿真 -> UART 下载
```

代码生成支持 HoneyGUI 和 LVGL 两个目标引擎，由项目 `project.json` 的 `targetEngine` 决定。

## 技术栈

- TypeScript 严格模式、VS Code Extension API
- React 19、Zustand、Webpack 5
- `fast-xml-parser` 处理 HML
- Three.js、Lottie 等用于特定组件预览
- SCons 用于 HoneyGUI 仿真，CMake 用于 LVGL PC 仿真

## 扩展启动

`src/extension.ts` 创建 `ExtensionManager`。管理器注册命令、侧边栏、状态栏、HML 自定义编辑器、仿真服务和 UART 服务，并检查当前工作区项目。

扩展还启动仅用于本机设计工作流的 HTTP API。项目启用 AI 资产时，扩展把 `vibe-designer/skills/honeygui-designer/` 分发到项目，并维护项目根 `AGENTS.md` 的托管区块。

## HML 编辑链路

### 打开文件

`.hml` 由 `HmlEditorProvider` 作为 `CustomTextEditorProvider` 打开。每个面板拥有独立的 `HmlController`，由 `DesignerPanel` 组装以下模块：

- `FileManager`：加载、保存、重载、文件快照和跨文件扫描
- `MessageHandler`：Webview 到扩展端的消息入口
- `SaveManager`：保存事务与并发编辑保护
- `AssetManager`：资源扫描、选择和转换配置
- `ComponentManager`：组件相关宿主操作

### 初始加载握手

初始数据必须等待 Webview 就绪：

```text
resolveCustomTextEditor
  -> FileManager.loadFromDocument（只解析）
  -> Webview 发送 ready
  -> MessageHandler 发送项目配置
  -> FileManager.reloadCurrentDocument
  -> Webview 收到 loadHml
```

`loadHml` 除当前组件外，还包含项目配置、项目国际化目录、所有 HML 文件和视图、其他文件组件 ID、GUI 版本以及仿真状态。加载阶段会把 `hg_view` 的显示尺寸校正到项目分辨率。

### 外部修改和保存

编辑器同时监听 VS Code 文档变化和磁盘文件变化，以支持文本编辑器、AI 工具、格式化器和 Git 操作。监听器通过防抖、保存事务 ID 和 `PendingWriteRegistry` 避免循环重载。

Webview 的 Zustand Store 保存内存编辑态，并向宿主报告脏状态。保存时 Webview 发送组件数据，扩展端更新 HML 文档、序列化并应用 `WorkspaceEdit`。撤销和重做同样发往扩展端，由 `FileManager` 的内容快照处理。

## Webview 结构

```text
App
├── Toolbar
├── 左侧面板
│   ├── ComponentLibrary
│   ├── AssetsPanel
│   └── ComponentTree
├── DesignerCanvas
└── PropertiesPanel / ConversionConfigPanel
```

`DesignerCanvas` 使用 React DOM 渲染组件，负责缩放、平移、拖拽、调整尺寸、框选和对齐。它不是 Fabric.js 画布。特定 3D 组件和资源预览才使用 Three.js。

`App.tsx` 目前承担宿主消息分发，`store.ts` 管理组件、选择、剪贴板、画布、脏状态、项目配置、项目国际化和导航关系状态。

## 代码生成

`CodeGenerationService` 找到项目后调用 `CodeGenerator`。后者扫描 HML 文件、解析组件并读取项目配置，再由 `CodeGeneratorFactory` 创建目标引擎生成器：

```text
project.json.targetEngine
  ├── honeygui -> HoneyGuiCCodeGenerator
  └── lvgl     -> LvglCCodeGenerator
```

生成文件遵循不同生命周期：

- `*_ui.c/h`：每次生成覆盖
- `*_callbacks.c`：保护区外可更新，保护区内用户代码保留
- 用户源文件：只创建一次，不允许生成器覆盖

共享资源、项目国际化、入口视图和 ROMFS 配置通过 `CodeGenOptions` 传入生成器。

## 编译仿真

`SimulationService` 接收命令并创建 `SimulationRunner`。Runner 按流程执行代码生成、资源转换、构建和运行。

- HoneyGUI：使用 `lib/sim/` 中的预编译库和 SCons 构建流程。
- LVGL：使用 `lvgl-pc/` 中的 CMake 工程配置、编译并启动模拟器。

修改仿真流程时必须同时检查两个引擎分支，不能假设它们共享相同的底层构建命令。

## 常见开发任务

### 添加或修改组件

通常需要同步检查：

1. `src/webview/types.ts` 的组件类型
2. `src/webview/components/ComponentLibrary.tsx` 的组件定义和引擎支持
3. `src/webview/components/widgets/` 的设计器预览
4. `src/webview/components/properties/` 的属性编辑器
5. `src/codegen/honeygui/` 和 `src/codegen/lvgl/` 的引擎实现
6. `vibe-designer/skills/honeygui-designer/references/hml-spec.md`
7. `docs/HML-Spec-zh.md`

### 添加资源类型

至少同时修改：

- `src/designer/AssetManager.ts`：扫描和识别扩展名
- `src/webview/components/AssetsPanel.tsx`：分类、计数和渲染
- 相应的转换服务和转换配置（如需要）

### 用户可见文本

- 扩展端：`vscode.l10n.t()`，同步 `l10n/bundle.l10n.json` 和中文文件
- Webview：`t()`，同步 `src/webview/i18n/locales/en.ts` 和 `zh-cn.ts`
- `package.json` 命令：使用 `%key%` 并同步 `package.nls*.json`

## 构建与测试

安装与标准构建：

```cmd
npm install
npm run compile
npm run build:webview
```

修改代码后必须执行：

```cmd
npm run compile && npm run build:webview
```

可用检查：

```cmd
npm run lint
npm run test
npm run test:e2e
npm run test:perf
npm run test:templates
```

`npm run test` 包含工具单元测试和 `src/test/jest` 下的源代码测试。扩展 E2E、性能和模板测试是独立脚本，不包含在默认测试命令中。

## 调试

- 按 F5 启动 Extension Development Host。
- 扩展端日志位于 Output 面板的 HoneyGUI 通道。
- Webview 使用 VS Code 开发者工具检查控制台和 DOM。
- HML 未刷新时，依次检查 `ready`、`loadHml`、保存事务 ID 和文件 watcher 日志。
- 代码生成问题先确认 `project.json.targetEngine`，再进入对应引擎目录。
- 仿真问题先区分 HoneyGUI/SCons 与 LVGL/CMake 分支。
